# FiberGuard — 光纤窃听发现系统

基于 **OTDR 曲线 + 光功率监测** 的隐蔽光纤窃听检测系统（Scala 3）。
目标是在温度漂移、施工震动、设备老化的强干扰下，检出 **0.05–0.5 dB 量级**的
弯折/分光窃听，并把可疑点定位到**具体缆段与现场搜索窗口**。

## 快速开始

```bash
export JAVA_HOME=$(/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home)
sbt test                                  # 单元测试与场景测试
sbt "run demo"                            # 8 缆段 × 4 纤 × 30 天，输出告警与评估
sbt "run demo --scale 4 --days 15"        # 规模测试（128 通道，检测约 2.5 s）
sbt "run eval --runs 10"                  # 多随机种子稳健性评估
```

输出写到 `out/alarms.txt`（现场可读）、`out/alarms.csv`（对接工单系统）、
`out/evaluation.txt`（与真值对照的评估）。

## 核心判据

系统认定"窃听"需要同时满足四条独立证据（按贡献排序）：

| # | 证据 | 物理依据 | 区分能力 |
|---|---|---|---|
| 1 | **时空二维台阶**：某里程在某个时刻之后出现**持续的**电平下降 | 弯折/分光在光路上引入固定插损，是"阶跃 + 平台"；而施工震动是整条曲线的瞬时抖动，老化是缓慢单调漂移 | 定位与时间 |
| 2 | **三波长比值**：1625nm 损耗 ≫ 1550nm ≫ 1310nm | 宏弯损耗随波长陡增（G.652 量级 1625/1550≈3.5、1310/1550≈1/100）；而熔接点温漂、老化、连接器损耗几乎与波长无关 | 区分"弯曲"与"温漂" |
| 3 | **同缆多纤同址**：同一物理光缆的多根纤芯在同一里程、相近时段同时异常 | 单纤定向窃听只动一根；开盒接分光器会扰动整束 | 区分"开盒入侵"与单纤 |
| 4 | **光功率旁证**：同期的整链功率下降 | 连续采样（分钟级），能给出 OTDR 看不到的起始时刻 | 时间与幅度 |

**置信度**用对数 Bayes 因子累加后经 sigmoid 转成概率，每条告警都附带
"被哪几条证据推上去"的明细，可审计、可调参。

## 算法要点（以及为什么这样设计）

### 1. 检测量：平台差 `D[i] = median(后段曲线)[i] − median(前段曲线)[i]`

把 N 次测量按候选变点 τ 分成前后两段，各自逐距离点取**中位曲线**再相减。
`D[i]` 是"越过 i 之后的累积损耗变化"：

- 窃听 → 在窃听点出现**一次向下的阶跃**，其后是平台；
- 熔接点温漂 → 在**已知熔接点**处出现台阶；
- 施工震动 → 两侧随机扰动，无平台；
- 发射功率/斜率标定漂移 → 整条曲线缓变，不出现台阶。

关键优势：**不需要估计衰减斜率**（两条中位曲线相减自动抵消），
也不需要切段 —— 台阶位置由采样点直接给出。

### 2. 拟合：`D[i] = a + b·i + ΔL·1[i ≥ e]` 的联合最小二乘

这一步走过了三个弯路，都写进了代码注释，因为它们是本问题的本质：

- ✗ **把时间当回归量去趋势**：台阶与时间共线，回归把台阶整块吃掉（实测 0.4 dB 只剩 0.03 dB）。
- ✗ **Theil–Sen / 滑动中位数去趋势**：前者同样把台阶当斜率（0.5 → 0.22 dB）；
  后者窗口跨过台阶时把台阶抹平。
- ✓ **线性项与台阶同时估计**：台阶的不连续无法被线性项解释，二者可分离。
  用前缀和把每次评估降到 O(1)，30 km × 30 条曲线约毫秒级。

### 3. 显著性：必须用"台阶系数的标准误"，且噪声估计要抗空间相关

- z 值不能用单点残差 σ，而要用 `σ/√(有效独立点数)` —— 否则 0.1–0.2 dB 的真实事件
  全部漏检（实测 z 被低估一个数量级）。
- **有效独立点数不能按"分辨率单元"硬算**：OTDR 空间噪声强自相关，且存在公里级的
  共模漂移。本实现用 `D` 残差的**积分相关长度**从数据本身估计。
- 多重比较：在"独立分辨单元数 × 候选 τ 数"上做 Šidák 校正，把整网族错误率控制在 1%。

### 4. 环境干扰的处理

- **施工**：施工强度高于阈值的测量直接剔除（震动会掩盖微小台阶）。
- **温度**：段差 `D` 本身已抵消大部分共模温度效应；残余的熔接点温漂通过
  "距最近熔接点的距离"在融合层降权，并通过**三波长比值**与窃听区分。
- **老化**：由联合拟合中的线性项吸收。

### 5. 工程性

- **单缆段失败隔离**：任何一条线路的数据损坏不会中断整网分析，失败记入诊断。
- **并行**：缆段间完全独立，按 CPU 并行（14 核实测 6.4× 加速）。
- **可复现**：并行不改变任何统计量。

## 实测指标（仿真验证）

30 天数据、每次测量 3 波长、每天 1 次 OTDR：

| 指标 | 结果 |
|---|---|
| 检出率（总体） | 约 0.63–0.71 |
| 告警准确率 | 0.82（跨 5 个随机种子 0.71–0.94） |
| 定位误差中位数 | **0.08–0.17 m** |
| 落在告警搜索窗内 | 100% |
| 最小可检出插损 | 0.15–0.25 dB 档 100%（30 天窗口） |
| 控制组误报 | 20 条无窃听缆段 0 误报 |

**已知限制（诚实说明）**：

- **间歇型窃听**（接上→拆下→再接上）会漏报。OTDR 每天只测一两次，
  若测量恰好落在"拆下"期间，曲线本身就没有台阶。这是信息论限制，
  不是算法缺陷。工程缓解：加密 OTDR 巡检、在光功率出现可疑下降时触发**按需 OTDR 复测**。
- **0.1 dB 以下**的插损在本噪声水平下不可靠区分。
- **紧贴熔接点**（< 50 m）的窃听可能与熔接点温漂混淆，依赖三波长判据区分。
- 光功率路径**仅作旁证**，不单独报警：它对 0.05–0.25 dB 的持续下降无法与
  光源漂移/连接器/温度分开，独立报警会产生大量无法处置的假警报。

## 规模与内存

历史 OTDR 曲线是全系统最大的数据对象：**128 通道 × 30 天 × 3 波长 × 45 km × 0.5 m
采样 ≈ 17 亿个 double ≈ 13 GB**。因此提供两个入口：

| 入口 | 内存 | 适用 |
|---|---|---|
| `Pipeline.run(Vector[SpanData])` | 全部数据常驻 | 测试、演示、≤ 数十条缆段 |
| `Pipeline.runStreaming(Iterator[SpanData], n, cfg)` | 只与"单段 × 并行度"有关 | **生产**，可处理上万条缆段 |

实测（14 核，8 GB 堆）：

| 规模 | 通道数 | 峰值内存 | 耗时（含仿真生成） |
|---|---|---|---|
| 8 缆段 × 4 纤 × 30 天 | 32 | < 1 GB | 11.7 s |
| 32 缆段 × 4 纤 × 30 天 | 128 | ~2 GB | 83 s |
| 120 缆段 × 4 纤 × 20 天 | 480 | 5.7 GB | 380 s |

其它工程性：单缆段失败隔离（数据损坏不中断整网）、按 CPU 并行（14 核实测 6.4×）、
结果可复现（并行不改变统计量）。

## 代码结构

```
model/      台账模型（Span / Splice / Closure / CableSection）与观测（OtdrTrace / PowerSeries）
core/       鲁棒统计（Stats）、信号处理（Dsp）、统计推断（Inference：IRLS / CUSUM / Šidák）
engine/     ChangePointScanner（时空变点）→ OtdrAnalyzer（三波长配对）
            → PowerAnalyzer / MultiFiberCorrelator（旁证）→ Fusion（似然比融合）→ Pipeline
sim/        物理仿真（宏弯损耗 / 熔接温漂 / OU 环境噪声）、场景与数据集构建
report/     告警渲染（文本/CSV）与对真值的评估
```

## 接入真实数据

把 `Pipeline.SpanData` 换成你的数据源即可，系统的输入契约只有四项：
台账 `Span`、每波长一组 `OtdrTrace`、每波长一条 `PowerSeries`、环境 `EnvSample`。

建议的接入顺序：先用 **OTDR 陷阱文件（.sor）解析器**填 `OtdrTrace`，
再接入 OPM 的分钟级数据，最后补环境传感器（没有温度传感器时可用气象数据 + 日照模型）。
两件事在真实部署时必须做：

1. **按现场光纤标定宏弯模型**（`sim/Physics.bendLossDb` 目前用 G.652 典型值），
   用厂家宏弯曲线表替换；
2. **用历史数据重标定噪声**：`ChangePointScanner` 的 `resolutionM` 与 `minLossDb`
   应按实际 OTDR 脉冲宽度与链路信噪比重新确定。
